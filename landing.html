Run Claude Code or Codex from your phone.
You tap to start. You tap to push.

Phodex is an open-source, self-hostable mobile app and backend for running AI coding agents from a phone. The Flutter app sends tasks to a FastAPI backend that drives Claude Code, OpenAI Codex, or Anthropic Managed Agents behind one worker interface and streams progress over Server-Sent Events. The agent is launched only after you tap Approve, and Phodex runs its own commit-and-push step only after you confirm on the phone. The backend runs on your own laptop (paired by QR code) or on a server you deploy; the code is MIT-licensed on GitHub, built by one developer, Gaurav Singh, as a portfolio project.

Send a task from your phone, watch Claude Code, OpenAI Codex or Anthropic Managed Agents work live, and tap Approve before the agent starts and again before Phodex commits and pushes. Open source, MIT.

Features

Approval before launch, approval before push

Your phone shows the exact command line and working directory the agent will be started with; it does not run until you tap Approve. When it finishes, you see the changed files and tap again to commit and push, or discard. With the Anthropic Managed Agents engine, each shell command is a separate approval.

Real-time streaming

Watch task progress live via Server-Sent Events — messages, tool calls, and file changes.

Push notifications (bring your own Firebase project)

Alerts when a task needs approval, completes or fails, once Firebase Cloud Messaging is configured.

Multi-repo support

Sync and manage multiple repositories. Select the target project and branch per task.

Encrypted keys

API keys and GitHub tokens are encrypted at rest, decrypted only for the duration of a task, and scrubbed from logs.

Three engines, one interface

Claude Code CLI, OpenAI Codex CLI, or Anthropic Managed Agents, behind a shared WorkerEngine adapter. The engine is chosen per deployment (WORKER_ENGINE), not per task.

How it works

01

Run the backend

Start PostgreSQL and Redis with docker compose and run the FastAPI backend on your laptop with WORKER_ENGINE set to claude or codex; the worker uses the Claude Code or Codex CLI you are already logged into. Or deploy the same backend to a server of your own with RUNTIME_MODE=cloud using the included Dockerfile and fly.toml; in that mode it clones GitHub repositories itself.

02

Build the app and pair your phone

Run flutter run from the mobile directory; Phodex is not in any app store. Choose My desktop and scan the QR code served at /pair on your laptop (same Wi-Fi, or Tailscale for remote access), or choose Phodex Cloud, which targets the server URL compiled into the app at build time with --dart-define=PHODEX_CLOUD_URL. Sign in with Google using your own OAuth client IDs, or with the demo account if the server you run enables one.

03

Create a task

Pick a repository (desktop: synced from your laptop by backend/scripts/device_agent.py, metadata only, so the phone gets no file or shell access; cloud: connect a GitHub repository URL and the server clones it) and describe the work. The worker engine, Claude Code CLI, Codex CLI, or Managed Agents, is fixed per deployment by WORKER_ENGINE, not chosen per task.

04

Approve the run and watch

With initial approval on (the default), the phone shows the command line the backend will run, the working directory, and an operator-configured risk label, and the task waits until you tap Approve or Reject. After that the CLI runs unattended; with Managed Agents, each bash command is a separate approval. Messages, tool calls, and terminal output stream to the Session screen over Server-Sent Events, and you can reply mid-task or stop it.

05

Commit and push

When the task finishes, tap Commit & Push on the phone to see the list of changed files (git status) and set a commit message. Tap Commit & push to commit and push them, or Discard to leave them uncommitted (a cloud workspace is also reset). Phodex itself never commits or pushes without that tap. With the Managed Agents engine the agent pushes from Anthropic's sandbox after your per-command approvals, and this step does not apply.

Worker engines: Claude Code, OpenAI Codex, Anthropic Managed Agents

Claude Code

Anthropic's Claude Code CLI (claude -p … --output-format stream-json), on your laptop or in a cloud runtime you host.

OpenAI Codex

The OpenAI Codex CLI (codex exec --json), not Codex inside the ChatGPT app. In the cloud image you add it yourself.

Anthropic Managed Agents (beta API)

Anthropic hosts the agent loop and a per-session sandbox; the repo is mounted through Anthropic's git proxy so your token is not placed inside the sandbox; every bash call becomes a phone approval. Cloud runtime only.

Two runtimes: your laptop, or a cloud runtime you host yourself

Desktop runtime

The backend runs on your laptop, paired by QR code over Wi-Fi or Tailscale. Tasks run against repos already on disk with the Claude Code or Codex CLI you are logged into; your git credentials never leave the machine and no Phodex server ever sees them.

Phodex Cloud (self-hosted)

Deploy the same backend to Fly.io or any Docker host with RUNTIME_MODE=cloud. It clones your GitHub repos into a workspace and runs Claude Code there (Codex if you add it to the image), or hands execution to Anthropic Managed Agents' hosted sandbox. Pushes use your encrypted GitHub token after you approve. No laptop needed — and no public instance: you run it.

Same app, same approval gate, same event stream. The runtime is a one-tap choice during onboarding and can be changed any time from Account.

Why open source and self-hosted

  • Nothing sits between your phone and your repository except software you run, plus the AI vendor's API that the Claude Code or Codex CLI itself calls, exactly as when you run the CLI by hand. In desktop mode the backend runs on your laptop, the phone connects over your LAN or a Tailscale network, the worker uses the Claude Code or Codex login already on the machine, and git push uses the laptop's own credentials. No git credential or AI provider key is sent to any Phodex server.
  • In cloud mode you operate the server. GitHub tokens and AI provider keys are stored with Fernet encryption under a key you generate, decrypted only when a git operation or task run needs them, handed to that subprocess through its environment, and scrubbed from streamed logs. There is no public Phodex instance: you deploy it (Dockerfile, fly.toml and a smoke test are included).
  • The approval gate is inspectable. The code that holds a task in waiting_approval until you tap Approve, and the git prepare, Commit & push, and Discard flow, is in the public repository, so you can read what runs before you tap instead of trusting a description. With the Claude and Codex engines the CLI runs unattended after that first tap; with Managed Agents every bash command is its own approval.
  • One interface, three engines. Claude Code CLI, OpenAI Codex CLI, and Anthropic Managed Agents (beta) are adapters behind the same WorkerEngine interface, selected per deployment with one environment variable, so the app is not tied to one model vendor or one CLI. Self-hosting and multi-engine support are not unique in this niche; what Phodex combines is a native Flutter app, a FastAPI backend you deploy, QR/Tailscale pairing, this specific trio of engines, and one mobile approval UI.
  • Bring your own keys and limits. A per-user Anthropic key, a server-wide key, or an existing CLI login all work; concurrency limits, rate limits, demo repository allowlists, and metrics (Prometheus, Jaeger) are yours to configure.
  • The trade-off is operational. There is no hosted Phodex service and no store listing; push notifications and Google sign-in need your own Firebase and OAuth setup. Phodex is a single-developer portfolio project, released under the MIT License.

Frequently asked questions

What is Phodex?

Phodex is an open-source (MIT), self-hostable mobile app plus backend that lets a developer create, watch, and approve AI coding tasks from their phone. The Flutter app talks to a FastAPI backend that drives Claude Code, OpenAI Codex, or Anthropic-hosted Managed Agents behind one worker interface, and tasks stream live over Server-Sent Events. By default the agent process does not start until the developer taps Approve on the phone, and Phodex's own commit-and-push step is a separate confirm-or-discard tap. The source is on GitHub under the MIT License, written by a single developer.

Can I run Claude Code from my phone?

Yes. With Phodex you run Claude Code from your phone by sending tasks to a backend that launches the Claude Code CLI headlessly. The backend runs claude -p <prompt> --output-format stream-json on your laptop (desktop runtime) or on a server you deploy (cloud runtime), and streams the agent's messages and tool calls, including the file edits it makes, back to the app as a live log. Your phone creates tasks, sends follow-ups, cancels, and approves; it does not get a shell or file browser.

Does Phodex work with OpenAI Codex?

Yes. Phodex supports the OpenAI Codex CLI as a worker engine alongside Claude Code and Anthropic Managed Agents. Setting WORKER_ENGINE=codex makes the backend run codex exec --json for each task, with the same approval gate, live event stream, and cancellation as the Claude worker. In desktop mode it reuses your logged-in local Codex CLI; the cloud Docker image installs only Claude Code by default, so Codex has to be added to the image. This is the Codex CLI, not Codex inside the ChatGPT app.

Does Phodex support Anthropic Managed Agents?

Yes, as a third worker engine (WORKER_ENGINE=managed), in the cloud runtime only. Anthropic Managed Agents is a beta API: Anthropic hosts the agent loop and a per-session sandbox, and Phodex maps the session's events onto tasks, messages, and approvals. Every bash command the agent wants to run becomes an approval on your phone, and the agent commits and pushes from Anthropic's sandbox after you approve those commands. The engine needs an Anthropic API key, a one-time agent/environment setup script, and a GitHub token; so far the adapter has been tested against a scripted fake client.

What is a human-in-the-loop approval gate for AI coding agents?

A human-in-the-loop approval gate means an AI agent cannot take a consequential action until a person explicitly approves it. In Phodex the gate is a tap on your phone: by default a task waits in a waiting_approval state and the Claude or Codex process is not launched until you approve. After that single approval the CLI runs unattended inside the task (Claude with --permission-mode bypassPermissions by default, Codex in a workspace-write sandbox), and Phodex's own commit-and-push flow is a separate confirm-or-discard step on your phone. With the Managed Agents engine, every bash command the agent wants to run becomes its own approval request.

How do I approve AI code changes from my phone?

Phodex has two approval taps. The Approvals screen gates starting the agent: each request shows the command line the backend will run (prompt elided), the working directory, an operator-configured risk label, and a description, with Approve and Reject buttons; rejecting can include a reason. Then, before Phodex pushes anything, a 'Commit & push to GitHub' sheet lists the changed files from git status, lets you edit the commit message, and offers Discard or Commit & push. It is a file-level list, not a line-by-line diff.

Do I need to keep my laptop on to use Phodex?

In Phodex's desktop runtime, yes: the backend and the Claude or Codex CLI run on your laptop, so when it is closed nothing runs. The phone pairs over the same Wi-Fi by scanning a QR code at the backend's /pair page, or from anywhere using Tailscale, ngrok, or Cloudflare Tunnel. The cloud runtime removes the laptop requirement by running the same backend on a server you deploy, but no public Phodex Cloud server is hosted.

What is the difference between the Phodex desktop runtime and cloud runtime?

The desktop runtime runs the Phodex backend on your laptop, works on repositories already on disk, inherits your claude login session, and pushes with that machine's existing git credentials. The cloud runtime (RUNTIME_MODE=cloud) runs the same backend on a server you deploy: it clones GitHub repositories into per-user workspaces, registers a synthetic 'Phodex Cloud' device, uses a server-wide or per-user API key, and pushes with an encrypted GitHub token. Tasks, approvals, the event stream, and commit-and-push share the same code paths in both modes; the visible difference is that discarding changes resets the cloud workspace, while on desktop it leaves the working tree dirty for local inspection.

Is Phodex Cloud available to use right now?

No public Phodex Cloud instance is hosted. The cloud runtime is written (Fly.io config, a Dockerfile with the Claude Code CLI, a CI deploy job, a smoke test, a demo-account endpoint), but the CI deploy job skips itself until a FLY_API_TOKEN secret exists. To use it today, deploy your own instance on Fly.io or Railway with Postgres and Redis and build the app with --dart-define=PHODEX_CLOUD_URL pointing at it. The demo account only exists when the operator sets DEMO_ACCOUNT_EMAIL and DEMO_ACCOUNT_PASSWORD.

How does Phodex handle my GitHub token?

In desktop mode Phodex stores no GitHub credentials: commit and push are git subprocesses on your laptop that reuse the SSH key, gh CLI, or credential manager configured there. In cloud mode, a GitHub token saved from the app is Fernet-encrypted at rest, passed to git through an inline credential helper so it never appears in a remote URL, and scrubbed from logs. With the Managed Agents engine, Phodex sends your GitHub token (your stored one, or the server's default) to Anthropic's API as the repository's authorization token; by Anthropic's design their git proxy uses it to mount the repo, so the token is not placed inside the agent sandbox itself.

Is Phodex open source?

Yes. Phodex is released under the MIT License; the full source for the Flutter app and FastAPI backend is at github.com/GAURAV-1313/phodex. You can read, clone, build, modify, and self-host it.

Is Phodex free?

Phodex has no price, paid tier, or billing code: it is a self-hosted project you run yourself. Your real costs are the AI provider and hosting you supply: a logged-in Claude Code or Codex CLI on your laptop, or your own Anthropic or OpenAI API key, plus, for the cloud runtime, a server such as Fly.io with hosted Postgres and Redis (the deploy guide uses Neon and Upstash, which offered free tiers when it was written). The app's 'Current plan' label only distinguishes a personal workspace from a managed one; it is not a billing tier.

Is Phodex on the App Store or Google Play?

No. Phodex is not in the App Store or Google Play and has no TestFlight. You build the Flutter app from the public GitHub repository with flutter run on an emulator, simulator, or your own device; a UI-only mock mode is available with --dart-define=PHODEX_USE_NETWORK=false. Push notifications and Google sign-in are implemented but need your own Firebase project and Google OAuth client IDs: until Firebase is configured, the Notifications screen shows a 'not set up on this build yet' message and pushes are a silent no-op; until OAuth clients are configured, Google sign-in will not succeed.
